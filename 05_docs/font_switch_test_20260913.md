# 완성형 A/B/A 실행 및 시험 이미지

**사용자 정정 반영: 굵은 글꼴 시험판은 사용 대상에서 철회했다. SFC 자료는 번역 참고용이며, 사용자는 기존 1비트 완성형의 외형 유지를 원했다. 아래는 수행했던 진단의 역사 기록이다. 사용자 요청에 맞는 새 시험판이 완성됐다는 뜻이 아니다.**

기존 글꼴을 지우는 진단에서 실제 완성형 두 묶음을 교체하는 시험으로 진행했다. 사용자 목표는 축약·글리프 제약을 위한 의역 없이 완성형 글꼴을 사용하는 것이다.

## 입력과 생성

기존 v0.99W의 RAM/디스크 글꼴과 Galmuri11 v2.24.29를 같은 12px 설정으로 래스터화한 비트맵을 정확히 대조했다. 1,245개의 한글 슬롯을 중복 후보 없이 식별했다. 이 슬롯만 같은 문자의 Galmuri11 Bold 비트맵으로 교체했다. 나머지 291슬롯은 보존했다. 기존 기록의 1,247자 전체를 복원했다고 주장하지 않는다.

Galmuri는 https://github.com/quiple/galmuri 의 기성 글꼴이다. 이번 굵은 글꼴은 변화를 식별하는 시험 재료이며 최종 미관 선택이 아니다. 추가 한글을 새 문자 코드로 표시하는 시험도 아니다.

## 실행 중 교체

기존 진단 상태와 입력을 재사용하고, 별도 에뮬레이터 프로세스의 RAM 폰트를 A→B로 교체했다. 메뉴 복귀 시험은 150프레임에 B→A로 복원했다. 각 쓰기는 변경 전 바이트가 예상 폰트와 일치해야만 실행된다.

| 경로 | 결과 |
|---|---|
| 기존 메뉴 유지 | VRAM 전체 차이 0 |
| 새 메뉴 문구 | 455픽셀 차이, 문구 영역에 한정 |
| A 복원 후 메뉴 재표시 | VRAM 전체 차이 0 |
| 새 맵 대화 | 1,288픽셀 차이, 대화 영역에 한정 |
| 전투 1·30·60프레임 | VRAM 전체 차이 0 |
| 전투 120프레임 | 162픽셀 차이 |
| 전투 300·600프레임 | 118픽셀 차이, 대사 영역에 한정 |

비교 이미지를 직접 확인했다. 기존 UI는 유지되고 새 UI 문구만 굵어진다. 맵 및 전투 화면의 관측 배경·초상화·효과는 보존된다. 원래 의미의 동일 문자가 출력되며 굵기만 바뀌는 것을 표본 문구에서 확인했다.

## 사용자용 시험 파일

`03_output/font_probe/SRW4S_font_B_test.bin`과 `.cue`를 만들었다. STAYDAT/C_DEMOG의 전각 폰트 사본 두 곳만 변경했다. 각 파일에서 폰트 바이트 18,809개가 바뀌었고, 변경 섹터는 총 50개다. ISO 배치·파일 크기·스크립트·실행 코드·오디오를 변경하지 않았다.

수정 전 섹터의 EDC/ECC를 재계산해 원본과 일치하는지 먼저 검사했다. 수정 후에도 섹터 헤더 보존·허용된 사용자 바이트 범위·두 폰트 사본·섹터 검산을 확인했다. 새 이미지 콜드부팅 3,600프레임 후 캐릭터 설정 화면을 확인했고 RAM 전각 폰트 48KiB가 B와 정확히 일치했다. 기존 상태를 주입한 결과와 구분되는 디스크→RAM 도달 증거다.

기존 패치 이미지에 적용하는 xdelta도 생성하고 복원 결과가 시험 BIN과 SHA256으로 일치함을 확인했다. 원본 및 기존 패치 이미지는 수정하지 않았다.

## 한계

고정 B 글꼴 시험 BIN과 외부 도구의 A/B/A 진단은 서로 다른 검증이다. 게임 안의 글리프 로더·문자 ID 가상화·캐시 교체 정책은 아직 없다. 자동 캐시 구현 완료나 1,536칸을 넘는 문자 종류의 표시 성공으로 기록하지 않는다.

현재 실행 코어의 보유 BIOS는 권장 SHA1과 달라 경고가 있었다. 지원 BIOS·독립 에뮬레이터·전체 장면 검증이 남는다. 저장 단위는 16×16 1bpp이지만 이번 실험 자형은 기존 12px 래스터 설정을 따른다.

## SFC 참고 자료

제공된 일본판 3MiB ROM에 v1.06 IPS의 1,862개 레코드를 적용하면 제공된 4MiB 한글판과 정확히 일치했다. 기존 3MiB 영역에서 43,078바이트가 달라지고 1MiB가 추가됐다. 상세 해시는 `sfc_reference_survey.json`에 있다.

이 사실은 ROM 확장을 확인한 것이며, 추가 1MiB 전체가 글꼴 또는 대사라는 뜻은 아니다. 추가 영역을 PS1 1bpp 배치로 단순 해석한 표본에서는 글꼴을 식별하지 못했다. SFC 문자표·압축·대사 포맷은 미해석이며 PS1에 이식하지 않았다.

Snes9x libretro 코어로 제공된 한글 ROM을 새 부팅해 3,600프레임 실행했다. 주인공 설정의 한국어 문구와 한글 이름 입력 목록을 직접 확인했다. 화면 아래에 초성 선택 UI가 있으나, 입력 방법만으로 내부 글리프 저장을 조합형이라고 판정할 수 없다. 이 화면들은 향후 용어·메뉴 표현의 참고이며 이번 PS1 글꼴은 SFC에서 추출한 글꼴이 아니다. 사용한 SFC 코어는 공식 Libretro buildbot의 `nightly/windows/x86_64/latest/snes9x_libretro.dll.zip`에서 로컬 도구 폴더에 받았고 사용자 에뮬레이터 설정은 변경하지 않았다.

## 재현

`build_font_probe.py --source <기존 패치 Track1> --upstream <Einbroch 체크아웃> --font <Galmuri11.ttf> --alternate <Galmuri11-Bold.ttf> --output <로컬 출력>`

`run_font_switch_probe.py --evidence <기존 진단 상태 폴더> --fonts <앞의 출력> --core <mednafen_psx_libretro.dll>`

출력 폴더의 설정에는 추출 폰트 바이트가 포함되므로 Git에서 제외한다. 폰트 및 코어 바이너리도 로컬 도구 폴더에만 보관한다.
