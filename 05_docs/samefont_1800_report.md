# 기존 서체를 유지한 완성형 공급 시험

2026-09-13. 사용자의 정정에 따라 Bold 시험판을 사용하지 않았다. 원래 Galmuri11 Regular v2.24.29를 기존 래스터 설정으로 사용했으며, SFC는 번역 참고용으로만 취급했다.

## 시험한 것

기준 RAM 전각 폰트의 1,536개 비트맵과 비교해, 기존에 같은 비트맵이 없는 완성형 한글 1,800자를 선택했다. 겹치는 모양도 제외했다. 메뉴 문구의 앞 여섯 글자에 대응하는 슬롯 6개에 새 비트맵을 일시적으로 공급했다. 문장 바이트·종결자·제어 코드·디스크는 수정하지 않았다.

각 표본은 같은 에뮬레이터 상태에서 독립적으로 시작한다. 6자의 비트맵을 넣고 메뉴를 표시한 뒤, 원래 비트맵으로 복원한다. 복원 뒤에도 화면에 이미 찍힌 새 글자가 유지되는지 확인한다. 이를 서로 다른 300묶음에 반복했다.

화면에 나오는 임의 음절열은 기술 진단용이며 번역문이 아니다. 실제 게임 번역에 반영하지 않았다. 이 시험은 매핑된 글리프 원천을 공급하는 효과를 확인하는 것이고, 새 문자 코드 체계나 게임 내부 자동 로더를 구현한 것은 아니다.

## 결과

| 항목 | 결과 |
|---|---|
| 기존 폰트에 없는 서로 다른 비트맵 | 1,800자 |
| 각 표본에서 재사용한 슬롯 | 6개 |
| 독립 표본 | 300개 |
| 출력 직후 및 원래 폰트 복원 후 검사 | 총 600회 |
| 요청한 글자와 화면 픽셀의 불일치 | 0 |
| 진단 글자 영역 밖 기준 화면과의 불일치 | 0 |
| 전체 전각 폰트 원상복원 | 일치 |
| 표본 0·1·299의 복원 전후 VRAM 전체 | 일치 |

화면 검사는 요청된 유니코드를 기성 글꼴로 직접 그린 기준과 비교한다. 게임용 32바이트 배열을 다시 풀어 기대 화면을 만드는 방식을 사용하지 않는다. 따라서 주입 쪽 좌우 배치나 슬롯 연결 오류가 그대로 기대값으로 복제되는 것을 피한다.

첫 표본과 마지막 표본의 실제 화면도 확인했다. 현재 메뉴의 이 경로에서는 글자 시작 간격이 12픽셀이다. 저장 틀 16×16과 실제 전진 폭을 혼동하지 않는다. 이 관측값을 맵·전투의 모든 경로에 자동 적용하지 않는다.

## 실패 및 판정 범위

처음에는 메뉴를 닫고 다시 열어 연속으로 시험하려 했으나, '아니오'는 다음 진행으로 넘어갔고 취소·확인·Start 조합도 같은 모달을 반복 재생성하지 못했다. 첫 묶음의 글리프 검사는 통과했지만 두 번째 표본의 재표시 단계에서 실패했다.

이를 숨기고 연속 스트리밍 성공으로 기록하지 않는다. 최종 시험은 각 묶음마다 시작 상태를 복원하는 독립 시험이다. 1,800개 글자의 공급과 출력은 확인했으나 연속 플레이의 수명 관리, 자동 캐시 적중/교체 정책, 재진입 동작은 미검증이다.

이전 메뉴·맵·전투의 RAM 원천 교체 결과와 함께 보면 기존 서체를 유지한 RAM 공급 방안에 근거가 생겼다. 하지만 이번 1,800자 전수 표본은 메뉴 경로만 대상으로 했다. 전투·맵의 1,800자 검사까지 했다고 합산하지 않는다.

보유 BIOS 해시가 코어 권장값과 다른 환경 한계도 남는다. 새 BIOS를 제공받았거나 독립 코어 검증을 마친 것이 아니다.

## 시험 파일

`03_output/samefont_test/Run_12_samples.cmd`는 현재 PC의 로컬 자료를 참조해 12자 빠른 재검사를 실행한다. 같은 폴더의 결과 화면과 안내를 함께 본다. 완성된 패치 BIN이 아닌 **외부 RAM 공급 진단 도구**이며, 원본 게임 이미지를 수정하지 않는다. 실행 코어와 폰트·기준 상태는 기존 로컬 경로에 있어야 한다.

전체 검사는 다음과 같다.

```
python 02_scripts/probe_samefont_stream.py --evidence E:/4robot/vram_test --font 06_tools/galmuri/Galmuri11.ttf --output 03_output/samefont_1800 --core <local-mednafen-core> --count 1800
```

다음 단계는 게임의 실제 문구/페이지 처리 시점에 공급을 연결하는 내부 로더 조사이다. 제어 코드 확장, 글자 ID와 슬롯의 분리, 공통 UI와 전투 오버레이의 생존 기간을 먼저 확정해야 한다. 축약 없는 장문 삽입은 그와 별도 과제로 유지한다.
